3. Notes for building it

Behaviour

  • Opens as a pop-up (openModal) from the start page. Auto-opens the first time on a device; remembered with a localStorage key (wrapped in try/catch like save.js). A "See how it works" button replays it.
  • Autoplay: about 6 to 14 s per screen, about 50 s in all. Pause keeps the child on the screen. Back, Next, the dots, and the ← → keys move between screens. Skip and Esc close it at any time. The last screen has "Start exploring" and "Watch again".
  • Every screen has its words on the screen. No sound by default (a sound toggle can follow the existing sound rules).
  • Reduced motion: no autoplay, no animation, every screen shows its final state. The child moves with Next.
  • Touch and keyboard: every button is at least 48px, visible focus ring, focus moves into the pop-up and back to the button when it closes.

Content and files (suggested, to confirm with Habiba)

  • Words in data/content/tutorial.json, never in the code. Scene 4 takes the 6 rooms from the existing room list so the two can never disagree. Scene 5's example answers must follow the same rule as the real hints: built from the data, not typed in.
  • New files: js/tutorial.js, css/tutorial.css. Pip from pipSVG(), colours from css/theme.css, motion from css/motion.css (rise, pop, float).
  • Optional log event tutorial-viewed (screens seen, skipped or finished). Ask Habiba first, because a new event type also touches the thesis data dictionary.

Scene 5 depends on two other Round 3 changes

  • Hint answers the child can tap or drag into the box, then edit (Prof comment 3).
  • The room summary as a tab that can be reopened (Prof comment 6): shown here as the "About this room" tab on the card.
